글로벌 NPU 가이드
ℹ️
본 가이드는 기존 NPU(NC Player Unit) 체계가 글로벌 NPU로 전환되면서 달라지는 기획 및 목표, 지표 정의, 적재 방식, 테이블 구조를 정리한 개념 가이드입니다.
글로벌 통합 추진 배경
  • 기존 NPU는 NCK 기준으로 구축되어 글로벌 서비스 지표 비교/해석이 어려움
  • 글로벌 서비스 확장에 따라 권역별로 분산된 계정·인증 체계를 하나의 통합 구조로 정비할 필요성이 증가
  • 글로벌 통합 계정 기반 KPI 부재로, 권역·게임 간 지표 비교 및 성과 해석이 어려움
  • 각 지역마다 상이한 스키마·집계 기준으로 인해 일관된 사용자 단위 분석 수행이 불가
  • 글로벌에 적용 가능한 표준화된 통합 KPI와 사용자 분석 체계 구축 필요


글로벌 통합 NPU 목표
  • 1
    글로벌 사용자 단위 통합 체계 구축
    권역별로 분산된 계정·인증 데이터를 통합하여 전 세계 모든 서비스를 하나의 사용자 단위(Global NPU Key)로 식별할 수 있는 체계 마련
  • 2
    표준화된 글로벌 KPI Framework 확립
    권역·게임별로 상이한 지표 정의·스키마·집계 방식을 통일해 글로벌 단위에서 일관된 KPI 비교 및 분석이 가능한 구조 구축
  • 3
    글로벌 유저 행동 기반의 고도화된 분석 환경 제공
    유저 단위로 통합된 로그를 기반으로 Retention, Funnel, Cannibalization 등의 분석이 가능하도록 분석 체계 고도화
글로벌 NPU의 원천 — 통합 인증 체계
글로벌 계정 통합 진행 후 기존 NPU Key의 원천인 백업 인증이 NCK·NCA·NCT·NCJ 전 권역에서 백업인증이 필수로 진행됩니다.
백업인증은 PlayNC 마이페이지 내에서 통합 관리되며, 전 권역의 마이페이지는 NCK가 총괄 관리합니다.
⏳
검토 중 (2026-07-07 기준)
기존에는 핸드폰 번호가 디폴트 인증 수단이었으나, 최근 이메일과 핸드폰 번호 중 선택 가능하도록 검토가 진행되고 있습니다. 방향성은 KR 계정 외 글로벌 계정을 제한하는 쪽으로 논의 중이며, 확정 사항이 아니므로 추후 변경될 수 있습니다.

글로벌 NPU가 Apache Iceberg (format-version=2)를 채택한 이유:
  • 다중 권역에서 빈번한 스키마 변경 필요: 기존 데이터와 호환성을 유지하면서 새로운 컬럼 추가 가능
  • 대규모 데이터의 삭제/업데이트 작업 효율화: V2의 Position Delete로 삭제 연산 성능 대폭 향상
  • 장기적인 데이터 관리 안정성: ACID 트랜잭션 보장 및 별도 메타스토어로 안정적인 버전 추적
  • 멀티 권역 동시 처리: 대규모 데이터 동시 접근 시 데이터 일관성 보장

게임별일별 접속 NPU 수 · 총 플레이타임
fnpu_login을 서비스 코드 기준으로 집계하고, dnpu_svc_appgroup에서 서비스명을 붙입니다.
SELECT l.p_dt,
       s.svc_nm,
       COUNT(DISTINCT l.npu_key)        AS login_npu_cnt,
       ROUND(SUM(l.use_time) / 3600, 1) AS playtime_hr
FROM   da_npu.fnpu_login l
LEFT JOIN (SELECT svc_cd, svc_nm
           FROM da_npu.dnpu_svc_appgroup) s
       ON l.svc_cd = s.svc_cd
WHERE  l.p_dt BETWEEN '20260701' AND '20260720'
GROUP BY l.p_dt, s.svc_nm
ORDER BY l.p_dt, login_npu_cnt DESC;
권역별결제 NPU 수 · 매출 (VAT 포함/제외)
fnpu_payment의 region 컬럼으로 권역 단위 매출을 집계합니다. 금액은 환율 적용된 KRW 기준입니다.
SELECT p.region,
       COUNT(DISTINCT p.npu_key) AS pay_npu_cnt,
       SUM(p.pay_incl_vat)       AS rev_incl_vat_krw,
       SUM(p.pay_excl_vat)       AS rev_excl_vat_krw
FROM   da_npu.fnpu_payment p
WHERE  p.p_dt = '20260720'
GROUP BY p.region
ORDER BY rev_incl_vat_krw DESC;
국가별접속 NPU 수
fnpu_login의 country_cd 컬럼으로 국가 단위 접속 규모를 확인합니다.
SELECT l.country_cd,
       COUNT(DISTINCT l.npu_key) AS login_npu_cnt
FROM   da_npu.fnpu_login l
WHERE  l.p_dt = '20260720'
GROUP BY l.country_cd
ORDER BY login_npu_cnt DESC;
게임 × 국가특정 게임의 국가별 매출 · ARPPU
svc_cd로 게임을 지정합니다 (예: 리니지W = 116). 서비스 코드는 위 확인 가능 서비스 목록에서 검색할 수 있습니다.
-- 리니지W (svc_cd = 116) 기간 내 국가별 매출
SELECT p.country_cd,
       COUNT(DISTINCT p.npu_key)                              AS pay_npu_cnt,
       SUM(p.pay_incl_vat)                                    AS rev_incl_vat_krw,
       ROUND(SUM(p.pay_incl_vat) / COUNT(DISTINCT p.npu_key)) AS arppu_krw
FROM   da_npu.fnpu_payment p
WHERE  p.p_dt BETWEEN '20260701' AND '20260720'
  AND  p.svc_cd = 116
GROUP BY p.country_cd
ORDER BY rev_incl_vat_krw DESC;
장르별접속 NPU 수
dnpu_svc_appgroup의 category_cd를 거쳐 dnpu_category의 장르명과 연결합니다.
SELECT c.category_nm,
       COUNT(DISTINCT l.npu_key) AS login_npu_cnt
FROM   da_npu.fnpu_login l
JOIN   (SELECT svc_cd, category_cd
        FROM da_npu.dnpu_svc_appgroup) s
       ON l.svc_cd = s.svc_cd
JOIN   da_npu.dnpu_category c
       ON s.category_cd = c.category_cd
WHERE  l.p_dt = '20260720'
GROUP BY c.category_nm
ORDER BY login_npu_cnt DESC;
테이블 관계도 ERD · da_npu 스키마
fnpu_login이 접속·매출·상태·부정계정을 잇는 하위 허브 역할을 하며, dnpu_svc_appgroup과 dnpu_category(신규)는 다른 테이블과 직접 관계선 없는 독립 코드성(기준정보) 테이블입니다.
